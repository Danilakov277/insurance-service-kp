### Обязательные требования к ПО (из бланка задания)
- Java, архитектура клиент-сервер, многопоточный сервер, работа с БД через JDBC-драйвер производителя.
- Сервер: консольный или GUI; настройки без изменения кода (конфиг-файл / аргументы).
- Клиент: оконное приложение (Swing/JavaFX/AWT) — выбран Swing.
- Своя иерархия классов (не менее 5), расширение классов JDK; 2+ паттерна; инкапсуляция, перегрузка, переопределение, сериализация, интерфейсы/абстрактные классы, static-методы, обработка исключений.
- Бизнес-логика только на сервере; параллельная обработка запросов.
- Не менее 12 высокоуровневых вариантов использования (не считая CRUD).
- Авторизация всех пользователей; 2–3 роли (администратор, сотрудник/агент, клиент).
- БД: не менее 5 связанных таблиц, 3НФ, идентифицирующие/неидентифицирующие связи с мощностью, ссылочная целостность.
- Технологии актуальны на начало 2025; работа на Windows 7 и выше.
- Публичный репозиторий на GitHub, коммиты каждую неделю (историю задним числом не подделывать).

## Технические решения (2026-10-13)
- Проектные решения (роли, 17 вариантов использования, 9 таблиц БД, алгоритмы премии/выплаты/возврата, классы и паттерны) — в design.md. Код и записка должны им соответствовать.
- Код компилировать с `--release 8` (javac из JDK 21): так программа работает на Windows 7 с JRE 8 и на новых JRE. Не использовать var, records, text blocks, switch-выражения.
- Обозначения графической части: чертёж IDEF0 — «БГУИР КП 1-40 01 02-08 015 Д1», схема алгоритма — «... Д2», плакаты — «... ПЛ1..ПЛ3» (по аналогии с ПЗ; при замечаниях руководителя поменять).
- Записка собирается скриптами, а не правится руками: docs/content.py (текст) → docs/build.js (docx-js) → docs/postprocess.py (содержание с номерами страниц, счётчики в реферате). Сборка выполняется в облачной среде Claude (Linux, LibreOffice, node docx). Если студентка правит docx вручную — перенести правки в content.py, иначе они потеряются при следующей сборке.
- Диаграммы: tools/make_idef0.py, tools/make_idef1x.py (Graphviz), tools/make_usecase.py, uml/*.puml (PlantUML); чертежи — tools/make_drawing.py (рамка и штамп по ГОСТ 2.104, шрифт GOST type B).
- Лист «Задание» в записке — заглушка, вместо него подшивается подписанный бланк.
