### Обязательные требования к ПО (из бланка задания)
- Java, архитектура клиент-сервер, многопоточный сервер, работа с БД через JDBC-драйвер производителя.
- Сервер: консольный или GUI; настройки без изменения кода (конфиг-файл / аргументы).
- Клиент: оконное приложение (Swing/JavaFX/AWT) — выбран Swing.
- Своя иерархия классов (не менее 5), расширение классов JDK; 2+ паттерна; инкапсуляция, перегрузка, переопределение, сериализация, интерфейсы/абстрактные классы, static-методы, обработка исключений.
- Бизнес-логика только на сервере; параллельная обработка запросов.
- Не менее 12 высокоуровневых вариантов использования (не считая CRUD).
- Авторизация всех пользователей; 2–3 роли (администратор, сотрудник/агент, клиент).
- БД: не менее 5 связанных таблиц, 3НФ, идентифицирующие/неидентифицирующие связи с мощностью, ссылочная целостность.
- Технологии актуальны на начало 2025; работа на Windows 7 и выше.
- Публичный репозиторий на GitHub, коммиты каждую неделю (историю задним числом не подделывать).

## Технические решения (2026-10-13)
- Проектные решения (роли, 17 вариантов использования, 9 таблиц БД, алгоритмы премии/выплаты/возврата, классы и паттерны) — в design.md. Код и записка должны им соответствовать.
- Код компилировать с `--release 8` (javac из JDK 21): так программа работает на Windows 7 с JRE 8 и на новых JRE. Не использовать var, records, text blocks, switch-выражения.
- Обозначения документов (2026-10-13, по шаблонам Visio кафедры и примеру ведомости из СТП, прил. Д):
  ПЗ — «БГУИР КП 1-40 01 02-08 015 ПЗ»; ведомость документов — «БГУИР КП 1-40 01 02-08 015 Д1» (форма 2, последний лист ПЗ, Лист = Листов = число страниц ПЗ);
  чертёж IDEF0 — «ГУИР.425707.015 Д2»; схема алгоритма — «ГУИР.425707.015 Д3»; плакаты — «ГУИР.425707.015 Д5», листы 1–3.
  Номер 015 взят из шифра ПЗ; в шаблонах кафедры стоят чужие номера (008, 024). При замечаниях руководителя менять константы CODE_* в tools/make_graphics.py.
- Записка собирается скриптами, а не правится руками: docs/make_pz.sh = content.py (текст, docs/content_*.py по разделам, построитель docs/pz.py) → autosplit.py (через LibreOffice UNO: абзацы подтягиваются перед альбомными рисунками, длинные таблицы делятся с «Продолжение таблицы N») → build.js (docx-js) → postprocess.py (содержание с номерами страниц, счётчики реферата) → ведомость (tools/make_graphics.py N ved) → PDF. Источники нумеруются автоматически в порядке первой ссылки (pz._renumber_sources). Сборка выполняется в облачной среде Claude (Linux, LibreOffice, node docx). Если студентка правит docx вручную — перенести правки в content_*.py, иначе они потеряются при следующей сборке.
- Диаграммы: tools/make_bpmn.py (BPMN 2.0), tools/make_idef0.py, tools/make_idef1x.py (Graphviz), tools/make_usecase.py, tools/make_classes.py + uml/*.puml (PlantUML), tools/flowchart.py (схемы алгоритмов ГОСТ 19.701), tools/make_arch.py; графическая часть и ведомость — tools/make_graphics.py (рамки по форматкам ЕСКД из tools/templates) → graphics/*.pdf.
- Лист «Задание» в записке — заполненный бланк (docs/Задание_КП_Балащенко.docx, даты сдвинуты на 2026/2027), вставлен страницами-картинками docs/zadanie-1.png, zadanie-2.png; подписанный бланк подшивается вместо них.
- Приложение А (Антиплагиат) — только страница-заголовок, отчёт студентка вставляет сама.
- Рисунки в ПЗ (2026-10-13, по замечанию студентки и СТП п. 2.5.3–2.5.4, прил. Н): все страницы книжные; широкие рисунки (fig(..., landscape=True)) не выносятся на альбомные листы, а поворачиваются на книжной странице так, чтобы читать с поворотом записки на 90° по часовой стрелке (верх рисунка у корешка, подпись справа снизу вверх; build.js rotatedFigure). Рисунок отделён от текста и подписи пробельной строкой.
- Рамки графической части (2026-10-13): строятся по форматкам ЕСКД из архива Altium_Templates студентки (tools/templates/GOST_A4_1.SchDot — форма 1, GOST_A4_2.SchDot — форма 2а; разбор CFB — tools/cfb.py), шрифт GOST Common оттуда же. А4 — только книжный (по ГОСТ 2.301 альбомный А4 не допускается). Плакаты — материал вписан в рамку того же листа (рамка и основная надпись на лицевой стороне), отдельной оборотной стороны нет.
